# Плагины: что ставить и в каком порядке

Список с версиями — `plugins.txt` в корне. Здесь про то, как это делается руками и что
пойдёт не так.

## Как ставить

Два пути, оба рабочие.

**Через интерфейс.** `Настройки → Плагины → Маркетплейс`, в поиске имя пакета, кнопка
«Установить». После установки — перезапуск приложения. Это путь по умолчанию: он не
требует терминала, и версия подбирается сама.

**Через терминал.** Если в системе есть команда `dsh`:

```
dsh plugin --profile desktop add dsh-steward
dsh plugin --profile desktop list
dsh plugin --profile desktop remove dsh-steward
```

На macOS `dsh` отдельно не устанавливается: команда живёт внутри приложения и в PATH
может не попасть. Проверка — `which dsh`. Пусто — идите через интерфейс, не тратьте
время на поиск бинарника.

## Порядок установки

Ставить всё разом — верный способ получить непонятную поломку. Порядок такой:

1. **`dshmarket`** — без него в интерфейсе нет нормального поиска плагинов. Если он уже
   в комплекте, пропустите шаг.
2. **`dsh-steward`** — сторож установки. Нужен первым, чтобы дальше было кому диагностировать.
3. **`@noob-stupid/dsh-plugin-console`** — выключатель плагинов. Ставится до всего
   остального, чтобы потом, если интерфейс сломается, было чем отключить виновника.
4. Остальные по одному, с перезапуском после каждого. Один плагин — один перезапуск.

Причина проста: если после установки пяти штук разом что-то сломалось, виновника искать
в пять раз дольше. По одному — виновник всегда последний.

## Что каждый делает

| Пакет | Зачем |
|---|---|
| `dsh-steward` | ловит падения плагинов, дрейф настроек, показывает бюджет окна, держит резервные копии правил |
| `@noob-stupid/dsh-plugin-console` | список плагинов с выключателями; спасает, когда раздел «Плагины» не открывается |
| `dshmarket` | поиск и установка из интерфейса |
| `dsh-auto-continue` | если ход упал на лимите, квоте или сетевом сбое — досылает «продолжай» сам |
| `dsh-context` | показывает состав контекста: что занимает окно и сколько осталось |
| `dsh-notify-me` | системные уведомления: ответ готов, пришёл запрос разрешения |
| `@goodandready/dsh-russian-lang` | русский интерфейс |
| `@changfenhuang/dsh-genui` | карточки, таблицы, шаги и графики внутри ответа |
| `@linxin666/dsh-client-ui-skill-explorer` | витрина скиллов: что подключено, что запускалось |
| `@michengai/dsh-archive-manager` | архив диалогов, избранное, восстановление |
| `dsh-chat-import` | импорт переписки из Claude, ChatGPT, Codex и других форматов |
| `dsh-skill-scoreboard` | счётчик вызовов скиллов: видно, что реально работает |
| `dsh-whale-widget` | баланс и расход DeepSeek в углу интерфейса |

## Где живут плагины

```
~/.dsh/profiles/desktop/package.json     ← список зависимостей
~/.dsh/profiles/desktop/node_modules     ← сами плагины
~/.dsh/profiles/desktop/cordis.patch.yml ← их настройки
```

`package.json` — обычный файл зависимостей. Если плагин не грузится, первым делом
смотреть, есть ли он в этом списке и есть ли папка в `node_modules`.

## Чего в списке нет и почему

В личном наборе автора есть плагины под его среду: мост в браузер с его логинами,
сортировка сессий под его привычку, замок модели, счётчик плагинов, виджет его стиля.
В чистой установке они либо не работают (нет расширения в браузере, нет ключей), либо
навязывают чужие привычки. Поэтому в стартовый набор они не входят: сначала база,
потом личные надстройки, когда поймёте, чего не хватает именно вам.

## Если плагин сломал интерфейс

Симптом: приложение запускается, но раздел «Настройки → Плагины» пустой или падает.

1. Не переустанавливать всё приложение.
2. Открыть `~/.dsh/profiles/desktop/cordis.patch.yml`, найти запись виновника и поставить
   ей `disabled: true`.
3. Перезапустить DSH, зайти в интерфейс, убрать плагин штатно.

Если не помогло и конфиг под подозрением — вернуть `cordis.patch.yml.bak`.
