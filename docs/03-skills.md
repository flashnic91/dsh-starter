# Скиллы: что это и как поставить

Скилл — папка с файлом `SKILL.md`. Внутри: короткое описание, когда применять, и порядок
работы. Ассистент сам читает описание и подгружает скилл, когда задача совпадает. Это не
команды, которые надо помнить: срабатывает по смыслу.

Каталог скиллов:

```
~/.agents/skills/
├── using-superpowers/SKILL.md
├── brainstorming/SKILL.md
├── design-ecosystem/SKILL.md
└── ...
```

Полный список — `skills.txt` в корне. Двадцать шесть штук, три группы.

## Группа 1: цикл разработки (15, ставится одной командой)

Это проект Superpowers, открытый, ставится копированием:

```
git clone https://github.com/obra/superpowers.git /tmp/superpowers
cp -R /tmp/superpowers/skills/* ~/.agents/skills/
```

Проверить, что приехало:

```
ls ~/.agents/skills | wc -l
```

Что даёт эта группа. Не «инструкции», а порядок работы, которого ассистент держится сам:

| Скилл | Что меняет |
|---|---|
| `using-superpowers` | вход во всё остальное: сначала думаем, потом пишем |
| `brainstorming` | выясняет, что реально нужно, до первой строки кода |
| `writing-plans` | план по шагам, а не «сейчас всё сделаю» |
| `executing-plans` | выполнение плана без прыжков в сторону |
| `test-driven-development` | сначала падающий тест, потом код |
| `systematic-debugging` | сначала причина, потом правка |
| `verification-before-completion` | «готово» только после проверки, с доказательством |
| `requesting-code-review` / `receiving-code-review` | ревью туда и обратно |
| `dispatching-parallel-agents` / `subagent-driven-development` | несколько задач одновременно |
| `using-git-worktrees` / `finishing-a-development-branch` | отдельные ветки и аккуратное слияние |
| `writing-skills` | писать свои скиллы |
| `diagnosing-superpowers` | разбор, почему сессия пошла не так |

Заметка для честности: копии в `~/.agents/skills` со временем отстают от репозитория.
Обновление — повторить `cp -R` после `git pull` в клоне.

## Группа 2: знание самого DSH (4)

| Скилл | Зачем |
|---|---|
| `dsh-doc` | справочник по самому DSH: настройки, плагины, пресеты, API. Уже в комплекте с приложением, ставить не надо |
| `official-plugins` | что умеет приложение из коробки — до того, как искать плагин |
| `personalized-pages` | как сделать свою страницу или панель внутри DSH |
| `find-skills` | поиск и установка скиллов по описанию задачи |

Первые три — то, что экономит часы: вместо «а можно ли в DSH…» ассистент смотрит
справочник и отвечает по факту. `find-skills` полезен, когда не хватает умения: сначала
поиск готового, потом свой скилл.

## Группа 3: дизайн и текст (7)

Дизайн: `design-ecosystem` (роутер, который сам выбирает объём работы),
`design-taste-frontend`, `impeccable`, `modern-web-guidance`.
Текст: `humanizer` (убирает машинный тон), `ru-text` (русская типографика и редактура),
`caveman` (короткий ответ без воды).

`design-ecosystem` — самый ценный из этой группы. Он включается до первой строки кода на
любую видимую работу: сайт, экран, панель, баннер. Без него ассистент делает «нормально»,
с ним — по маршруту из проверок.

## Ставить всё сразу или по частям

Цикл разработки — ставить сразу, он работает в связке. Остальные — по мере надобности:
лишний скилл не мешает, но и пользы не даёт, пока задача не встретится.

Проверка, что скилл виден: спросить ассистента «какие скиллы подключены» или открыть
витрину скиллов (плагин `skill-explorer`).

## Свои скиллы

Папка `~/.agents/skills/моё-название/` с файлом `SKILL.md`:

```markdown
---
name: моё-название
description: Когда применять. Это описание читает ассистент, чтобы понять, срабатывать или нет.
---

# Что делать

1. Шаг.
2. Шаг.
```

Правило одно: в `description` писать ситуацию, а не название. «Когда пользователь просит
свести таблицу из CSV» сработает, «скилл для CSV» — нет.

Писать свои скиллы лучше после первого месяца работы: станет видно, что вы объясняете
ассистенту каждый раз одними словами. Это и есть скилл.
